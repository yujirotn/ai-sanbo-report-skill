# 今日のまとめレポート（AI参謀）

今日の作業を1枚のレポートにまとめ、本人が同意した範囲だけを、SHO-SANへの事例として回収できる形にする。
**送信・アップロードはしない。** 作るのは「回収用」フォルダとzipまで。送るのは本人がメールで行う。

## 0. 最初に同意を確かめる（必ず1問目）

次の3つから選んでもらう。答えが出るまで先へ進まない。

```
今日のまとめを1枚のレポートにします。SHO-SANへの事例として使ってよい範囲を選んでください。
A. 社名を出して、事例として使ってよい
B. 社名は伏せて（「地域の住宅会社」などとして）使ってよい
C. 自社の振り返りだけにする（SHO-SANには渡さない）
おすすめ：迷ったら B です。どれを選んでも、数字・人名・お客様の情報は出しません。
```

- C のときは、レポートだけ作って `回収用` フォルダもzipも作らない
- A・B の選択は、レポートの下に「掲載の範囲：A（または B）／同意日」と1行書く

## 1. 集める（読むだけ）

このフォルダの中から、次の「大枠」だけを拾う。ファイルの中身の数字や文章は写さない。

| 拾うもの | どこから | 拾い方 |
|---|---|---|
| 作ったスキル | `.agents/skills/` または `.claude/skills/` の各 `SKILL.md` | 名前・説明（description）・何をするか1行 |
| 作ったファイル | `資料/` など、今日作られたファイル | 種類（Excel・PowerPoint・Word・HTML）と用途だけ。ファイル名に人名・社名・物件名があれば書かない |
| ルールの変化 | `AGENTS.md` または `CLAUDE.md` | 追加された約束の種類だけ（例：メールは送信しない） |
| 今日の流れ | 本人に聞く／会話 | 章ごとに何をしたか1行 |

次の3問を、1問ずつ本人に聞く（答えはそのまま短く使う。盛らない）：
1. 今日いちばん「使える」と思ったことは？
2. 明日から実際に使うものは？
3. 難しかった・止まったところは？

## 2. 伏せる（いちばん大事）

レポートにも回収用のファイルにも、次は**一切書かない**。見つけたら言い換えるか、消す。

- 人名（本人以外）、お客様の名前・住所・電話・メール
- 金額・件数・売上・棟数・割合などの**数字**（「毎月の実績表」のように、仕事の種類で書く）
- 物件名・店名・取引先名・社内の固有の呼び名
- パスワード、URL、ファイルの保存場所、システムのログイン情報
- 社内で「言いにくい」と話した内容、経営課題の中身（プロフィールのファイルは読んでも書かない）
- 同意が B のときは、社名・地名も伏せる（「地域の住宅会社」「九州の工務店」など）

ツール名（Excel、Outlookなど一般の製品名）は書いてよい。社内専用のシステム名は、A のときだけ書く（B は「基幹システム」と書く）。

## 3. レポートを作る（1枚のHTML）

決まったひな形は使わない。中身に合わせて、このときに1枚のHTMLを自分で組み立てる。
`回収用/YYYY-MM-DD_今日のまとめ.html` に保存する（C のときは `資料/` に保存）。

入れる中身（この順・1枚に収める）：
1. 見出し：今日のまとめ（日付・掲載の範囲）
2. 今日やったこと：章ごとに1行（4〜6行）
3. 作ったスキル：名前／一言の説明／頼み方の例／数えた数字（手順の数・決まりの数・出来上がるもの・頼んでから出来るまでの実測時間）
4. 使いみち（活用事例）：このスキルで、どんな仕事がどう変わるか2〜3件。削減時間は測れないので書かない。「毎月の転記が一言になる」のように書き、効果は1か月後に測る項目として「次に測るもの」に置く
5. 本人の声：3問の答え（短く・本人の言葉のまま）
6. 次の一手：明日から1つ・来月1つ

作り方の決まり：
- 1ファイルで完結させる。外部のファイルやネットのURLは読み込まない
- 色は、この会社の資料作成スキルにメインの色があればその色、無ければ落ち着いた1色。文字の羅列にせず、表・カード・流れ図など、中身に合う形で見せる
- 印刷しても、スマホで開いても崩れないようにする
- 「2. 伏せる」で決めたことを守る（数字・人名・お客様の情報を書かない）

できたら本人に開いてもらい、「伏せ忘れが無いか」「見た目の希望」を聞いて直す。

## 4. スキルと事例カードを回収用にまとめる（A・B のときだけ）

回収するのは「スキルそのもの」と、その事例カード。SHO-SANが他社でも使える事例として貯めるため、どの会社でも同じ項目で書く。

### 4-1. スキル本体
1. 作った各スキルのフォルダを `回収用/skills/<スキル名>/` にコピーする（`SKILL.md` と手順に必要な文章ファイルだけ。画像・ロゴ・データファイルはコピーしない）
2. コピーした方だけを直す：決まりの表や例に入っている固有の値（店名・人名・数字・列名・ファイル名・URL・社内の固有の呼び名）を `【伏せ字】` に置き換える。手順・表の形・質問の仕方は残す（ここが再利用したい中身）
3. 元のスキルは書き換えない

### 4-2. 事例カード（スキル1本につき1枚）
`回収用/skills/<スキル名>/事例.md` を、次の形で書く。**数字は今日その場で数えた・測ったものだけ**。削減時間や効果の見込みは書かない（測れないため）。

```
---
skill: <スキル名>
date: YYYY-MM-DD
industry: 住宅（新築注文住宅）など業種だけ。社名は書かない
user_role: 使う人の役割（例：新築事業部の責任者）
category: 集計・資料・メール・相談・調べもの・自動化 のどれか
tools: [Excel, PowerPoint など一般の製品名]
consent: A または B
---
## 何の仕事を楽にするか
（1〜2行。仕事の種類で書く）

## 入れるもの → できるもの
- 入れるもの：（例：基幹システムから出した物件一覧のCSV）
- できるもの：（例：月次の実績表1枚、グラフ3つ、要点3行）

## 数えた数字（今日の実測）
| 項目 | 数 |
|---|---|
| 手順のステップ数 | （SKILL.md の手順を数える） |
| 決まり（表）の項目数 | （決まりの表の行を数える） |
| 1回で出来上がるもの | （ファイルの種類と量） |
| 頼んでから出来上がるまで | （今日の実行で測った時間。測っていなければ「未計測」） |
| 今日の実行回数／うち直した回数 | （会話の記録から数える） |

## 頼み方
（いちばんよく使う一言）

## つまずいたところ・直したこと
（今日の直しの記録から、伏せて書く）

## 他社で使うときに変えるところ
（決まりの表のうち、会社ごとに変わる項目の名前だけ）
```

### 4-3. 全体のまとめ
`回収用/まとめ.md` に、スキルの一覧（名前・category・1行説明）と、本人の3問の答え（伏せたもの）、次の一手を書く。レポートのHTMLもここに入れる。

## 5. 最後の確認とzip

1. `回収用` に入れたもの（レポート1枚＋スキル何本）を一覧で見せ、「この内容でSHO-SANに渡してよいですか？」と聞く
2. OKなら `回収用` をzipにして、場所を伝える。止めると言われたら、zipを作らない
3. 「このzipを、担当者へのメールに添付して送ってください」と伝えて終わる。**自分で送らない・アップロードしない**

## してはいけないこと

- 同意の前に、回収用のファイルを作る
- 数字・人名・お客様の情報を、レポートや回収用のスキルに入れる
- 元のスキルやファイルを書き換える・消す
- メール送信・アップロード・外部への共有
